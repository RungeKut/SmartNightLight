# Протокол: WebSocket и HTTP

Браузер и устройство общаются по WebSocket на `/ws`. Формат — JSON,
ArduinoJson 7.x на устройстве.

## От устройства к браузеру

### `fullState`

Снимок системного состояния. Отправляется при подключении и по запросу
`getFullState`.

```json
{
  "type": "fullState",
  "device": "SmartNightLight-B92046",
  "ap_mode": false,
  "ap_ssid": "SmartNightLight-B92046",
  "wifi": "connected",
  "wifi_rssi": -74,
  "ip": "192.168.88.20",
  "time_valid": true,
  "time_hhmm": 2146, "time_sec": 5,
  "date_year": 2026, "date_month": 9, "date_day": 17,
  "manual_on": false,
  "brightness": 0,
  "mode": "off",
  "uptime": 15,
  "heap": 38176,
  "ws_clients": 0,
  "ws_drops": 0,
  "config_pending": false
}
```

| Поле | Смысл |
|------|-------|
| `mode` | `off`, `manual`, `signal`, `dim`, `sleep`, `sunrise` |
| `time_valid` | пришло ли время с NTP; если `false`, расписание не работает |
| `ws_drops` | отброшенные куски входящих сообщений, см. `WsRxBuffer` |
| `sound_level` / `sound_peak` | размах с микрофона: текущий и за минуту |
| `sound_present` | микрофон отвечает; `false` — вход болтается |
| `sound_active` | отклик на шум идёт прямо сейчас |
| `mqtt_error` | почему брокер отказал, текстом |
| `ota_pending` / `ota_remaining` | прошивка ждёт подтверждения |
| `config_pending` | есть несохранённые настройки, ждут отложенной записи |

### `telemetry`

Тот же набор полей, тип `telemetry`. Рассылается всем клиентам раз в секунду.

Кадр молча пропускается, если очередь отправки занята:

```cpp
if (ws.count() == 0) return;
if (!ws.availableForWriteAll()) return;
```

Очередь клиента на ESP8266 — 8 сообщений, и при переполнении библиотека по
умолчанию **рвёт соединение**. Для страницы настроек это выглядело бы как
самопроизвольный сброс формы, поэтому пропущенный кадр дешевле: следующий
придёт через секунду. Важные ответы идут адресно и не теряются.

При подключении клиенту выставляется `setCloseClientOnQueueFull(false)` —
вторая линия защиты от того же обрыва.

### `configState`

Настройки. Отправляется вторым сообщением снимка.

```json
{
  "type": "configState",
  "config": {
    "wifiSSID": "HomeNet",
    "deviceName": "",
    "defaultDeviceName": "SmartNightLight-B92046",
    "flags": 15,
    "manualBrightness": 160,
    "sleepTime": 2200, "sleepLength": 90,
    "signalBrightness": 255,
    "sunriseTime": 700, "sunriseLength": 60, "sunLength": 30,
    "sunriseBrightness": 255,
    "tzOffsetMinutes": 180,
    "signalMinutes": 5
  }
}
```

**`wifiPass` клиенту не отдаётся никогда.** Это проверяется автотестом
протокола: если поле появится в ответе, тест упадёт.

`signalMinutes` — длительность вспышек, приходит с устройства, чтобы
подсказка в интерфейсе не расходилась с прошивкой.

### `saveConfigResult`

```json
{"type": "saveConfigResult", "success": true, "restarting": false, "message": "Сохранено"}
```

`restarting` показывает, будет ли перезагрузка: она нужна только при смене
сети, пароля или имени устройства.

## От браузера к устройству

### `getFullState`

Запросить снимок. Отправка откладывается до `loop()` — см.
`docs/modules/core-loop.md`.

### `setManual`

Ручное управление. Применяется сразу, без перезагрузки.

```json
{"type": "setManual", "on": true, "brightness": 200}
```

`on` — состояние на сеанс, в EEPROM не сохраняется. `brightness` попадает в
`manualBrightness` и уходит в EEPROM отложенно.

### `saveConfig`

Сохранить настройки. Объект `config` обязателен: без него все поля ушли бы в
EEPROM пустыми, поэтому запрос без него отклоняется с `success: false`.

```json
{"type": "saveConfig", "config": { ... те же поля, что в configState ... }}
```

**Пустой `wifiPass` означает «оставить прежний».** Сервер пароль не отдаёт,
поэтому поле в форме всегда пустое, и без этого правила сохранение любой
настройки стирало бы пароль от WiFi.

### `restart`

Перезагрузить устройство.

### `confirmOta`

Подтвердить, что новая прошивка работает. Без подтверждения устройство
через пять минут перезагрузится один раз — см. `docs/build-flash.md`.
То же делает `GET /confirm` и кнопка в Home Assistant.

### `forgetWiFi`

Забыть сеть и поднять точку доступа. См. `docs/modules/wifi.md`.

## Сборка входящих сообщений: WsRxBuffer.h

ESPAsyncWebServer отдаёт данные так, как они пришли по TCP. Сообщение длиннее
одного сегмента (на ESP8266 это около 536 байт) приезжает несколькими
вызовами `WS_EVT_DATA`, а длинное — ещё и несколькими кадрами с opcode
`CONTINUATION`. `saveConfig` в один сегмент не помещается.

Наивная проверка «сообщение пришло одним куском» работает ровно до тех пор,
пока конфиг не подрастёт:

```cpp
if (info->final && info->index == 0 && info->len == len) { ... }   // так нельзя
```

В SmartWaterMeter именно это привело к тому, что настройки молча перестали
сохраняться после добавления новых полей — ни ошибки, ни записи в лог, ветки
`else` просто не было. Модуль перенесён оттуда целиком.

Особенности:

- Буфер фиксированный (`WSRX_MAX_BYTES` = 1536), а не `String`: куча на этой
  плате фрагментируется, и растущая строка на каждое сообщение — лишний
  источник измельчения ровно там, где следом ArduinoJson просит крупный
  непрерывный кусок.
- Сборка привязана к идентификатору клиента: кусок от другого клиента посреди
  набора отбрасывается, а не дописывается в чужое сообщение.
- Не поместившееся сообщение отбрасывается целиком. Обрезанный JSON
  разобрался бы с ошибкой и увёл бы диагностику не туда.
- Счётчик `drops()` виден в телеметрии как `ws_drops`.

## HTTP

| Маршрут | Что делает |
|---------|-----------|
| `GET /` | SPA из LittleFS, `Cache-Control: no-cache` |
| `GET /api.json` | снимок состояния, те же поля, что `fullState` |
| `GET /metrics` | метрики Prometheus, см. `docs/metrics.md` |
| `GET /confirm` | подтвердить прошивку после OTA |
| всё остальное | отдаётся `index.html` (SPA-роутинг) |

Кэш отключён потому, что после `uploadfs` страница должна обновиться сразу, а
LittleFS не хранит время записи файла — опереться на `ETag` или
`Last-Modified` нельзя.

`GET /api.json` удобен для Home Assistant, curl и мониторинга: не требует
WebSocket и не занимает слот клиента.

> Локальные адреса `192.168.x.x` на рабочей машине идут мимо системного
> прокси только с `curl --noproxy '*'` — иначе прокси отвечает 503.
