# Тесты

## Логика на хосте

```bash
pio test -e native
```

41 проверка в [test/](../test/): логика светильника в `test_nightlight`,
кривая яркости в `test_dimmer`. Покрывают арифметику времени, приоритет
режимов, кривые, границу полуночи и вырожденные настройки.

Тесты возможны потому, что `NightLight.h` не зависит от Arduino: заглушки не
нужны, заголовок собирается обычным компилятором как есть. Это и есть главная
причина, по которой логика вынесена из `.ino`.

### Что именно проверяется

| Группа | Тесты |
|--------|-------|
| Время | разность в пределах суток, через полночь, преобразование hhmm |
| Приоритет | ручное перекрывает всё; сон выигрывает у рассвета при пересечении |
| Отход ко сну | вспышки в начале и их окончание через 5 минут, затухание, конец интервала, интервал через полночь |
| Рассвет | монотонный рост, выход на максимум, удержание заданного максимума после разгорания |
| Полночь | интервал засыпания минута за минутой через 00:00, монотонность яркости на границе, вспышки через полночь, предельные 255 минут |
| Шум | ночное окно (в том числе через полночь), разгорание, удержание, затухание, приоритет относительно других режимов |
| Кривая яркости | ноль остаётся нулём, любое ненулевое значение светится, монотонность при всех гаммах, границы |
| Вырожденное | разгорание 2 минуты, нулевые длительности, яркость ниже порога тления |

Три последних теста — регрессионные, каждый закрывает конкретный дефект
прежней версии. Их стоит читать вместе с `docs/modules/nightlight.md`.

### Хостовый компилятор на Windows

Системного `gcc` на рабочей машине нет, и `pio test -e native` падал с
`'gcc' is not recognized`. При этом MinGW уже лежит в пакетах PlatformIO —
его тянет за собой сборка под ESP8266.

[scripts/native_toolchain.py](../scripts/native_toolchain.py) добавляет
`packages/toolchain-gccmingw32/bin` в PATH сборки и линкует рантайм статически:

```python
env.PrependENVPath("PATH", mingw_bin)
env.Append(LINKFLAGS=["-static", "-static-libgcc", "-static-libstdc++"])
```

Статическая линковка обязательна: собранный тест запускается уже без этого
PATH, не находит `libstdc++-6.dll` и падает с кодом `0xC0000135`
(`STATUS_DLL_NOT_FOUND`) ещё до первой проверки. Симптом выглядит как
«тесты не работают», хотя компиляция прошла успешно.

На Linux и macOS каталога нет, скрипт молча ничего не делает.

### Unity требует setUp/tearDown

Даже пустые. Без них линковка падает на `undefined reference to 'setUp'`.

## Проверка на живой плате

Тесты на хосте не покрывают ни WiFi, ни WebSocket, ни PWM. Это проверяется
вручную; сценарий, по которому проверялось в последний раз, описан в
[sessions/2026-09-17-wifi-provisioning-port.md](sessions/2026-09-17-wifi-provisioning-port.md).

Минимальный набор после изменений в прошивке:

1. **Загрузка**: `pio device monitor` — имя устройства, причина сброса,
   подключение к сети или поднятие точки доступа.
2. **HTTP**: `curl --noproxy '*' http://<ip>/api.json` — время верное,
   `time_valid: true`, режим осмысленный.
3. **Телеметрия**: подключиться к `/ws` и убедиться, что кадры идут раз в
   секунду. Затем **отключиться и подключиться заново** — кадры должны идти
   снова. Именно этот шаг ловит §1 из `docs/pitfalls.md`.
4. **Расписание**: выставить сжатый интервал (разгорание 2 минуты) и
   посмотреть, как меняется `brightness`. Значения можно проверить руками по
   формулам из `docs/modules/nightlight.md`.
5. **Настройки**: сохранить, перечитать, убедиться, что поля совпали, а
   `wifiPass` в ответе отсутствует.

### Как проверить границу суток, не дожидаясь ночи

Часовой пояс — настройка, поэтому устройству можно показать любое время:

```python
new_tz = (целевое_время_в_минутах - utc_в_минутах)
```

Ставим смещение так, чтобы до 00:00 оставалось три-четыре минуты, задаём
короткий интервал засыпания вокруг полуночи и смотрим телеметрию. Так
проверялся переход 17.09.2026:

```
23:59  dim  35   ШИМ 15
00:00  dim  25   ШИМ 8     <-- полночь
00:01  dim  17   ШИМ 5
00:06  off  0    ШИМ 0
```

После проверки смещение надо вернуть.

> Замечание к шагу 4: сжатые интервалы удобно выставлять через WebSocket
> скриптом. Помните, что после проверки настройки надо вернуть — иначе
> светильник останется с ночным режимом в 21:39.

## Чего не хватает

- Автотест протокола не лежит в репозитории: сценарии прогонялись временными
  скриптами. Стоит оформить их в `test/` или отдельную папку `tools/`.
- Полный цикл точки доступа проверен 17.09.2026, когда на машине появился
  WiFi-адаптер: AP видна в эфире, раздаёт DHCP (клиент получил
  `192.168.0.100`), портал отдаёт страницу на `192.168.0.1`, сохранение сети
  через него возвращает устройство в STA.

  Замечание на будущее: `netsh wlan show networks` отдаёт кэш предыдущего
  скана. Свежеподнятая точка доступа появляется в списке не сразу — стоит
  повторить команду через несколько секунд, прежде чем решать, что AP не
  поднялась.
