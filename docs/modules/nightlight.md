# NightLight.h — логика светильника

Единственный модуль, который решает, что должно гореть. Не зависит от
Arduino, WiFi, EEPROM и `millis()` — поэтому собирается хостовым компилятором
и покрыт тестами (`docs/testing.md`).

## Формат времени

Время суток — `hhmm`: часы × 100 + минуты. 22:30 → `2230`.

Формат достался от первой версии прошивки и сохранён: в этом виде настройки
лежат в EEPROM и уходят в веб-интерфейс. Внутри все расчёты идут в минутах от
полуночи.

```cpp
uint16_t hhmmToMinutes(uint16_t hhmm);
uint16_t minutesToHhmm(uint16_t minutes);
uint16_t minutesSince(uint16_t startHhmm, uint16_t nowHhmm);   // всегда 0..1439
```

`minutesSince()` считает разность по модулю суток, поэтому переход через
полночь обрабатывается сам собой. Проверка попадания в интервал и позиция
внутри него — это одно вычисление:

```cpp
uint16_t elapsed = minutesSince(s.sleepTime, nowHhmm);
if (elapsed <= s.sleepLength) { /* внутри интервала, прошло elapsed минут */ }
```

> **Как было раньше.** Интервал паковался в одно 32-разрядное число:
> начало сдвигалось на четыре разряда влево и складывалось с концом, так что
> `22000830` означало интервал с 22:00 до 08:30. Попадание проверяла
> `checkTimespan()` с двумя ветками (обычный интервал и через полночь), а
> позицию внутри интервала считала отдельная функция. Два расчёта жили
> порознь и могли разойтись — например, при изменении длительности
> пересчитывался один и не пересчитывался другой.

## Настройки

```cpp
struct nl::Settings {
  uint8_t  flags;              // маска FLAG_*
  uint8_t  manualBrightness;   // яркость ручного включения
  uint16_t sleepTime;          // hhmm, начало отхода ко сну
  uint8_t  sleepLength;        // минут на засыпание
  uint8_t  signalBrightness;   // яркость вспышек и старт затухания
  uint16_t sunriseTime;        // hhmm, начало рассвета
  uint8_t  sunriseLength;      // минут на разгорание
  uint8_t  sunLength;          // минут держать максимум после рассвета
  uint8_t  sunriseBrightness;  // максимум рассвета
};
```

Биты `flags` совпадают с первой версией прошивки:

| Бит | Константа | Режим |
|-----|-----------|-------|
| `0x01` | `FLAG_SLEEP` | отход ко сну |
| `0x02` | `FLAG_SIGNAL` | вспышки «пора спать» |
| `0x04` | `FLAG_DIM` | затухание при засыпании |
| `0x08` | `FLAG_SUNRISE` | имитация рассвета |

Важная деталь: `signalBrightness` — это и яркость вспышек, и **стартовая
яркость затухания**. Не `manualBrightness`. Так было в первой версии, так
оставлено.

## Режимы на выходе

```cpp
struct nl::Result { uint8_t brightness; nl::Mode mode; };
```

| `Mode` | Строка в API | Что происходит |
|--------|--------------|----------------|
| `MODE_OFF` | `off` | погашен |
| `MODE_MANUAL` | `manual` | включён вручную |
| `MODE_SIGNAL` | `signal` | вспышки «пора спать» |
| `MODE_DIM` | `dim` | затухание |
| `MODE_SLEEP` | `sleep` | интервал сна без затухания |
| `MODE_SUNRISE` | `sunrise` | рассвет |

## Кривые яркости

Затухание и рассвет — одна и та же парабола с вершиной на краю интервала:

```
затухание: y(x) = min + (max-min) * ((L-x)/L)²   максимум в начале
рассвет:   y(x) = min + (max-min) * (x/L)²       максимум в конце
```

`min` = `MIN_BRIGHTNESS` = 3 из 255. Ниже этого значения светодиод не тлеет,
а мерцает, поэтому кривые туда не опускаются, и заданный максимум ниже 3
поднимается до 3.

Это кривые **расписания**: они говорят, какой должна быть заданная яркость
в каждый момент. Не путать с гамма-кривой из `src/Dimmer.h` — та переводит
уже полученную яркость в скважность ШИМ и отвечает за то, чтобы равные шаги
ползунка выглядели равными. Кривые независимы и применяются одна за другой:
сначала расписание решает «сколько», потом `Dimmer` — «каким ШИМ».

Проверено на плате при разгорании 2 минуты и максимуме 200: `3 → 52 → 200`,
где 52 = `3 + 197·(1/2)²`. И при затухании 45 минут с яркости 200: на восьмой
минуте 136 = `3 + 197·(37/45)²`.

> **Как было раньше.** Коэффициенты `a`, `b`, `c` считались отдельно для
> каждой кривой. Для затухания формула была алгебраически той же самой. А у
> рассвета знаменатель `L - L²/2` обращался в ноль при длительности ровно
> 2 минуты, и яркость становилась NaN. При обычных 60 минутах обе записи
> совпадают с точностью до единицы яркости.

### После разгорания

Пока идёт `sunLength`, держится заданный максимум. Прежняя версия скармливала
параболе время за пределами разгорания, кривая продолжала расти, и результат
обрезался до 255 — то есть при максимуме 100 светильник выходил на полную
яркость. Закрыто тестом `test_sunrise_holds_configured_maximum_after_ramp`.

## Главная функция

```cpp
nl::Result nl::compute(const Settings &s, uint16_t nowHhmm,
                       bool manualOn, bool blinkOn);
```

`blinkOn` передаётся снаружи: модуль не имеет права знать про `millis()`.

Порядок проверок и есть приоритет режимов — см. `docs/architecture.md`.

## Чего модуль не делает

Не знает, что времени может не быть. Если NTP ещё не ответил, `compute()`
честно посчитает режим для того времени, что ему дали. Гасит светильник в
этом случае вызывающий — `applyNightLight()` в `.ino`, см.
`docs/modules/core-loop.md`.
