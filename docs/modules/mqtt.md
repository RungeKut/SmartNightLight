# MqttClient.h — Home Assistant через MQTT

## Зачем, если уже есть /api.json

REST требует, чтобы Home Assistant опрашивал устройство и чтобы сущности
были описаны руками в YAML. MQTT переворачивает схему: устройство само
публикует данные в брокер и само себя описывает — сущности появляются в
HA без единой строки конфигурации.

REST и `/metrics` при этом остаются: они работают без брокера и удобны
для curl и Prometheus.

## Почему AsyncMqttClient

`PubSubClient::connect()` блокирует `loop()` до таймаута сокета. У нас в
цикле живут PWM и опрос микрофона — вставать нельзя. AsyncMqttClient
работает поверх ESPAsyncTCP, который в проекте уже есть ради
веб-сервера.

## Темы

```
smartnightlight/<MAC3>/state     телеметрия одним JSON
smartnightlight/<MAC3>/light     состояние лампы (JSON-схема HA)
smartnightlight/<MAC3>/status    online / offline (LWT)
smartnightlight/<MAC3>/cmd/+     команды от Home Assistant
homeassistant/<тип>/snl<MAC3>/<объект>/config   автодискавери
```

Базовая тема и идентификаторы строятся **от MAC, а не от имени
устройства**: имя пользователь может поменять, и тогда HA потерял бы
связь с уже созданными сущностями. Понятное имя уходит в `device.name`
автодискавери, и его смена просто переименовывает карточку.

## Что появляется в Home Assistant

| Сущность | Тип | Что делает |
|----------|-----|-----------|
| Ночник | light | ручное включение с яркостью |
| Яркость, Режим | sensor | что светильник делает прямо сейчас |
| Уровень шума, Пик за минуту | sensor | ночная активность |
| Срабатываний по шуму | sensor | counter для статистики |
| Отклик на шум | binary_sensor | `device_class: sound`, годится в триггер автоматизации |
| Режим сна / Рассвет / Реакция на шум | switch | включение режимов |
| Порог шума, Яркость отклика | number | подстройка без веб-интерфейса |
| RSSI, Аптайм, Память, Время синхронизировано | diagnostic | |
| Перезагрузить, Подтвердить прошивку | button | |

### Что означает лампа

Сущность `light` управляет **ручным включением**, а не подменяет собой
расписание:

- включили из HA — светильник горит поверх расписания;
- выключили — вернулся к своим режимам, и если сейчас идёт затухание
  или рассвет, он продолжит гореть по ним.

Фактическая яркость и текущий режим отдаются отдельными сенсорами,
чтобы было видно, чем светильник занят. Без этого «выключил, а он
горит» выглядело бы поломкой.

Лампа публикуется в отдельную тему `/light` в JSON-схеме: HA ждёт здесь
строго свой формат, и лишние поля рядом ему мешают.

## Автодискавери

Описания публикуются **по одному за проход `loop()`** с паузой 120 мс.
Полтора десятка сообщений по ~400 байт подряд исчерпали бы буферы TCP.

Ключи сокращённые (`stat_t` вместо `state_topic`) — HA понимает их
наравне с полными, а на ESP это экономит сотни байт на каждом
сообщении.

Публикуются с `retain`: HA восстановит сущности после своего
перезапуска, не дожидаясь следующей загрузки светильника.

`clearDiscovery()` снимает описания пустой retained-нагрузкой — штатный
способ убрать сущность из HA.

## Last Will

При обрыве связи брокер сам объявит устройство недоступным
(`status: offline`), и HA узнает об этом сразу, а не по таймауту. Все
сущности ссылаются на эту тему через `avty_t`.

## Диагностика: почему брокер молчит

Причина отказа показывается в веб-интерфейсе текстом, а не номером.
Это добавлено после того, как на живом брокере подключение молча не
устанавливалось, а в логе была только цифра:

```
[MQTT] Отключено: не авторизован: нужен логин и пароль (5)
```

Коды `AsyncMqttClientDisconnectReason`:

| Код | Значение |
|-----|----------|
| 0 | нет TCP-соединения |
| 1 | брокер не принял версию протокола |
| 2 | брокер отверг идентификатор клиента |
| 3 | брокер недоступен |
| 4 | неверный формат логина или пароля |
| 5 | не авторизован: нужен логин и пароль |
| 6 | не хватило памяти |
| 7 | не совпал отпечаток TLS |

Домашний брокер закрыт логином и паролем — анонимный брокер в домашней
сети означает, что любое устройство в ней может читать показания и слать
команды. Логин заводится на сервере в `/opt/mosquitto/config/passwd`, в
git его нет.

## Пароль

`mqttPass` клиенту не отдаётся, как и пароль от WiFi. Пустое значение в
`saveConfig` означает «оставить прежний» — иначе сохранение любой
настройки стирало бы пароль от брокера.

## Применение настроек

`applyConfig()` вызывается после каждого сохранения, поэтому смена
брокера подхватывается на лету, без перезагрузки устройства.
