# Wemos_Mini.ino — главный цикл

Единственный файл, который знает про железо. Вся логика светильника живёт в
`NightLight.h`, все настройки — в `ConfigStore.h`.

## Порядок в loop()

```cpp
ArduinoOTA.handle();
MDNS.update();
ws.cleanupClients(2);
WiFiupd();
updateLocalTime();
applyNightLight();
flushConfig();
handleSnapshots(now);
broadcastTelemetry();      // раз в секунду
// отложенная перезагрузка
delay(10);
```

`ws.cleanupClients(2)` стоит до всего остального не случайно — см.
`docs/pitfalls.md` §1. Без него телеметрия замолкает навсегда после первого
же закрытия вкладки.

## Время

```cpp
void updateLocalTime();
```

Обновляет `epochTime`, `timeValid`, `nowHhmm`, `nowSecond` и дату.

`NTPClient::getEpochTime()` отсчитывает время по `millis()` от последней
синхронизации, поэтому часы идут и при пропавшей сети. До первой
синхронизации он отдаёт смещение часового пояса плюс аптайм — то есть что-то
вроде 03:00 01.01.1970. Отличить это состояние можно только по дате:

```cpp
timeValid = (epochTime > 1600000000);   // сентябрь 2020
```

## Гашение без времени

```cpp
void applyNightLight();
```

Считает режим через `nl::compute()` и пишет яркость в PWM. Если времени нет и
светильник не включён вручную — гасит:

```cpp
if (!timeValid && !manualOn) { r.brightness = 0; r.mode = nl::MODE_OFF; }
```

Иначе `gmtime(0)` дал бы 00:00 01.01.1970, и интервалы срабатывали бы наугад:
устройство в AP-режиме считало бы, что сейчас полночь, и могло бы зажечься
посреди дня. Интерфейс в этом состоянии показывает предупреждение.

## Запись яркости

```cpp
void setBrightness(uint8_t value);
```

Пишет в PWM только при изменении значения. `lastWritten` объявлена как
`uint16_t` и инициализирована `0xFFFF`, чтобы первый же вызов с нулём прошёл,
а не был отсечён как «уже установлено».

## Отложенная запись настроек

`markConfigDirty()` запоминает момент, `flushConfig()` пишет EEPROM через
`SAVE_DEFER_MS` (30 секунд) после последнего изменения. Нужно из-за ползунка
яркости — подробности в `docs/modules/config.md`.

Перед плановой перезагрузкой несохранённое дописывается принудительно.

## Отложенная перезагрузка

```cpp
if (needsRestart && restartAtMs == 0) {
  restartAtMs = now + 500;
  Log.println(F("[System] Перезагрузка запланирована"));
}
```

Полсекунды нужны, чтобы ответ `saveConfigResult` успел уйти клиенту: он
только поставлен в очередь отправки, и сброс до её разбора оставил бы
браузер без подтверждения.

Сообщение печатается в момент планирования, а не перед самым `ESP.restart()`:
вывод асинхронный, и строка за миллисекунду до сброса до консоли не доедет.
Без этого штатную перезагрузку было бы не отличить от падения.

## Снимок состояния

Состояние отправляется новому клиенту двумя сообщениями (`fullState` и
`configState`), по одному за проход `loop()`, из `handleSnapshots()` — а не из
колбэка WebSocket.

Колбэк выполняется в контексте сетевого стека, и сериализация с отправкой
прямо оттуда роняет плату. `requestSnapshot()` только ставит отметку в один из
четырёх слотов; повторный запрос от того же клиента перезапускает отправку с
начала, а не занимает второй слот.

Если клиент отвалился, пока снимок ждал очереди, слот просто освобождается.

## Логирование

`Log` (из `Log.h`) — наследник `Print`, пишет в `Serial`. В нём оставлен
механизм `LogSink` на случай, если однажды понадобится Telnet-консоль, как в
SmartWaterMeter; сейчас приёмник не подключён.

Смысл в том, чтобы весь вывод шёл через одну точку: `Serial.print()` в обход
`Log` в новую консоль не попадёт.

## Константы

| Константа | Значение | Смысл |
|-----------|----------|-------|
| `LED_PIN` | 0 | GPIO0, он же D3 |
| `PWM_FREQ_HZ` | 1000 | частота PWM |
| `PWM_BITS` | 8 | диапазон 0..255 |
| `AP_SSID_PREFIX` | `SmartNightLight` | префикс имени и SSID |
| `AP_PASS` | `""` | открытая точка доступа |
| `BLINK_PERIOD_MS` | 200 | период вспышек |
| `SAVE_DEFER_MS` | 30000 | задержка записи EEPROM |
| `TELEMETRY_MS` | 1000 | период рассылки состояния |
| `SNAPSHOT_SLOTS` | 4 | одновременных отправок снимка |
