## Технологии

| Компонент | Чем сделано |
|-----------|-------------|
| Веб-сервер | ESPAsyncWebServer (асинхронный) |
| Фронтенд | LittleFS, одна HTML-страница, без сборки |
| Обмен данными | WebSocket + ArduinoJson 7.x |
| Настройки | EEPROM, одна структура с магическим числом |
| Время | NTPClient, `europe.pool.ntp.org` |
| Обновление | ArduinoOTA (по WiFi) и USB |
| Среда | PlatformIO, ESP8266 Arduino framework |

## Поток управления

```
loop()
  │
  ├─ ArduinoOTA.handle()      — приём обновления по WiFi
  ├─ MDNS.update()
  ├─ ws.cleanupClients(2)     — без этого телеметрия замолкает, см. pitfalls §1
  ├─ WiFiupd()                — поддержание STA или попытка уйти из AP
  ├─ updateLocalTime()        — epoch -> hhmm, флаг timeValid
  ├─ applyNightLight()        — настройки + время -> яркость -> analogWrite
  ├─ flushConfig()            — отложенная запись EEPROM
  ├─ handleSnapshots()        — по одному сообщению снимка за проход
  ├─ broadcastTelemetry()     — раз в секунду всем клиентам
  ├─ отложенная перезагрузка
  └─ delay(10)
```

Ничего не блокирует цикл дольше, чем на время подключения к WiFi (до 30 с в
`connectToWiFi()`, вызывается при старте и раз в 10 минут в AP-режиме).

## Разделение ответственности

Ключевое решение проекта — **логика светильника не знает про железо**.

`NightLight.h` — чистая функция: на вход настройки, время суток, флаг ручного
включения и фаза мигания, на выход яркость и режим. Ни Arduino, ни WiFi, ни
EEPROM, ни `millis()`. Благодаря этому она собирается хостовым компилятором и
покрыта тестами, а весь ввод-вывод остаётся в `.ino`.

```cpp
nl::Result r = nl::compute(settings, nowHhmm, manualOn, blinkOn);
setBrightness(r.brightness);
```

Фаза мигания приходит снаружи именно потому, что `millis()` — это тоже
железо. Вызывающий считает её сам:

```cpp
bool blinkOn = ((millis() / BLINK_PERIOD_MS) % 2) == 0;
```

## Приоритет режимов

Порядок проверки в `nl::compute()` и есть приоритет:

1. **Ручное включение** — перекрывает всё.
2. **Интервал отхода ко сну** (если включён и время внутри):
   - первые 5 минут — вспышки «пора спать», если включены;
   - иначе затухание, если включено;
   - иначе обычная яркость.
3. **Интервал рассвета** (если включён и время внутри).
4. Иначе — погашен.

Сон выигрывает у рассвета при пересечении интервалов. Это проверяется тестом
`test_sleep_wins_over_sunrise_on_overlap`.

## Адресация

| Режим | Адрес | Когда |
|-------|-------|-------|
| AP | `192.168.0.1` | SSID не задан или подключиться не удалось |
| STA | DHCP | обычная работа, плюс `http://<имя>.local` |

Имя устройства по умолчанию — `SmartNightLight-XXXXXX`, где XXXXXX — три
последних байта MAC. Оно же hostname, mDNS-адрес и SSID точки доступа.
