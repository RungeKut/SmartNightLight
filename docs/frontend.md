# Фронтенд

Одна страница — [data/index.html](../data/index.html), около 27 КБ. Ни сборки,
ни зависимостей, ни внешних запросов: устройство в AP-режиме работает без
интернета, поэтому CDN исключён.

Страница лежит в LittleFS и заливается отдельно:

```bash
pio run --target uploadfs
```

## Вкладки

### Светильник

- **Крупный показ состояния**: кружок-свечение, яркость в процентах, режим и
  сырое значение 0..255.
- **Ручное управление**: переключатель и ползунок, применяются сразу через
  `setManual`.
- **Время**: часы, дата, предупреждение если NTP ещё не ответил.
- **Система**: WiFi, RSSI, IP или SSID точки доступа, имя, аптайм, свободная
  память.

Прозрачность свечения считается как `0.15 + 0.85·√(b/255)`. Корень — потому
что воспринимаемая яркость нелинейна: без него слабое свечение на экране
выглядит темнее, чем светильник в комнате.

Отдельная карточка — **микрофон**: текущий уровень полосой, порог
красной риской поверх неё, пик за минуту и счётчик срабатываний. Без
этой шкалы порог пришлось бы подбирать вслепую, поэтому она на
дашборде, а не в настройках.

Сверху может появиться баннер подтверждения прошивки с обратным
отсчётом. Отсчёт тикает локально: телеметрия приходит раз в секунду, но
при потере связи цифра иначе застыла бы.

### Настройки

WiFi, имя устройства, часовой пояс, блоки режимов (отход ко сну,
вспышки, затухание, рассвет, реакция на шум), настройки MQTT, кнопки
сохранения, перезагрузки и «Забыть сеть». В AP-режиме сверху появляется
подсказка о том, что происходит.

Состояние MQTT показывается с причиной отказа: «не авторизован» и
«брокер недоступен» лечатся совершенно по-разному.

## Два правила, без которых интерфейс раздражает

### Форма не перерисовывается во время ввода

Телеметрия приходит раз в секунду. Если перерисовывать форму на каждый кадр,
незаконченный ввод затирается прямо под руками: набрали половину SSID —
и поле очистилось.

```js
let settingsDirty = false;
function updateSettings() {
  if (!state || !state.config || settingsDirty) return;
  ...
}
```

Флаг взводится на первое же `input`/`change` в любом поле вкладки и
сбрасывается после успешного `saveConfigResult`. Периодический запрос
`getFullState` раз в 30 секунд при взведённом флаге тоже не отправляется.

Ползунок яркости на вкладке «Светильник» защищён отдельно — флагом
`manualTouching` и проверкой `document.activeElement`.

### Ползунок не заваливает очередь

`oninput` срабатывает на каждое движение. Очередь клиента на ESP8266 — восемь
сообщений, и без ограничения она переполняется за пару секунд. Отправка
пропускается через таймер 150 мс, а на `onchange` уходит финальное значение.

## Разбор сообщений

```js
case 'fullState':   state = Object.assign(state || {}, msg); updateDashboard(); break;
case 'configState': state.config = msg.config; updateSettings(); break;
case 'telemetry':   Object.assign(state, msg); updateDashboard(); break;
```

Состояние приходит двумя сообщениями и **склеивается**, а не замещается:
`fullState` заводит объект, `configState` подмешивается. Так сделано потому,
что отправка одним куском роняла плату в соседнем проекте — см.
`docs/websocket.md`.

## Переподключение

При обрыве — попытка раз в 3 секунды, в шапке появляется «Переподключение...».
Раз в 30 секунд запрашивается свежий снимок: это и keep-alive, и страховка от
пропущенных кадров.

## Валидация

Ошибки показываются списком над формой, поля подсвечиваются красным,
сохранение не отправляется.

Числа разбираются через `num()`, а не через `parseInt(x) || default`:
последнее съедает валидный ноль, превращая «0 минут» в значение по умолчанию.
Запятая принимается как десятичный разделитель — `<input type="number">` при
вводе «1,5» отдаёт пустую строку, и без замены на точку значение молча
терялось бы.

## Тёмная тема

Через `@media (prefers-color-scheme: dark)`, отдельного переключателя нет.

## Правка страницы
